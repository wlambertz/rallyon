Verdict: **fail — return to G2**. Checker: `g3-value`, 2026-11-11. The proposed exposure rule depends on visibility that existing, unchanged draft authorization does not protect. The security boundary and potentially scope and effort require a new decision before issue decomposition.

| Severity | Finding and requested resolution |
| --- | --- |
| Blocking | `design.md` makes a previously hidden announcement visible again when its tournament becomes PUBLIC; `ANN-004` conditions reads on that same field. The proposed feature does not transition tournament status, so a published announcement can remain associated with a DRAFT. Existing `UpdateDraftService.execute` and `DraftReplacement.replaceDraft` check draft state and version but do not compare the actor with the creator; `TournamentMapper.applyScalars` persists the caller's supplied visibility. The existing configuration-read spec explicitly lets another authenticated user read even a PRIVATE configuration, including its version. Thus another authenticated user who can submit a valid replacement can switch visibility to PUBLIC and re-expose the announcement despite creator-only publication. Choose and specify a creator-controlled exposure mechanism, or propose an explicitly approved compatibility change to draft authorization; consider concurrent changes. Return the revised design/spec and its effect on effort to G2. |

State this limitation explicitly in the decision and validate with an organizer; do not claim a finished human-facing publishing experience. |
| Moderate | `design.md` defers the actual isolation/locking strategy for visibility races to an ADR, yet selects effort 5.
