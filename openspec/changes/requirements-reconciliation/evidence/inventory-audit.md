# Independent inventory audit for issue 183

- Checker: native agent `/root/inventory_audit`, independent of maker `codex`.
- Inputs: live issue [#183](https://github.com/wlambertz/rallyon/issues/183), including scope, acceptance criteria and reference sections 1–6; `inventory.md` and `analysis.md` in this change.
- Outcome: **not complete**. The files correctly identify themselves as working drafts; do not use this report as evidence that #183 or G5 is complete.
- Method: compared the six source sections and specified classification contract with the working inventory. This audit did not independently verify every DBV provision or inspect all production code. No assessment is made of source-rule correctness beyond the specific textual comparisons below.

## Blocking findings

1. **Classification contract is not fulfilled.** #183 requires each in-scope item to be Covered, Conflicts, Gap or Not applicable, or explicitly skipped with a reason. The working inventory introduces `P` for partial models and `G` as either a gap _or no demonstrated behavior_, and the initial evidence in `analysis.md` uses additional wording. This is useful nuance, but no consistent mapping is supplied to the requested four categories. Split a partially represented source requirement into separately classified covered representation and missing behavior, or provide an explicit decision rule with concrete code/spec evidence. Lack of demonstrated behavior is not necessarily proof of absence.
2. **Source-to-row coverage is not demonstrably complete.** Many rows aggregate distinct claims, with no source-location-level checklist or mapping that proves every §1–§6 feature, rule and non-functional claim has been classified or intentionally skipped. Examples requiring explicit treatment include §1's publication of M&Q report and ball-provision details; §2's entry confirmation versus corrections and locking; §3's handling of tied seed ranks; §4's source-specific three-match spacing in a team tie, no-show timer stages and separate officiating/medical subclaims; and §5's report deadline and individual card consequences. An overarching row is not enough to demonstrate disposition when parts differ in relevance, authority or classification.
3. **International deferrals are duplicated and grouped.** I1–I6 group multiple international-only items, then I7–I16 repeat many of the same items. The issue requests each international-only feature once as “international, deferred”. A deduplicated source-to-ID mapping is needed to prove both coverage and single disposition. Mixed rows must retain national/generic counterparts separately.
4. **Several out-of-scope conclusions lack the required reason.** N4-06, N4-07 and N4-09 classify entire coaching, equipment, medical, officiating and apparel groups as `X` because software value has not been demonstrated or they are human protocols. The requested issue scope explicitly retains generic tournament mechanics; lack of a demonstrated need alone does not establish that every distinct claim is not applicable. Classify each item separately, or explicitly mark it skipped with its actual scope rationale; defer deciding whether a valid gap is worth implementing until prioritization. Where a rule is international-only, label it separately rather than applying an entire group's status to it.
5. **Existing evidence and scope resolution remain incomplete.** `analysis.md` itself labels the gap for age classes pending a full code search. The covered/partial roster and configuration evidence does not establish draw, invitation, federation export, result, eligibility or publication behavior; the analysis correctly warns about this but does not yet provide a systematic absence search or map every item to an authoritative current spec/code location. The implementation-level classification and remaining unverified claims need independent rechecking after revision.
6. **Issue state and candidate disposition are stale.** `inventory.md` says no follow-up issue has been accepted, but [#203](https://github.com/wlambertz/rallyon/issues/203) has been approved and created. The output must record its URL and accurately distinguish an accepted analysis follow-up from an accepted implementation. The remaining candidate groups must receive explicit adopt/adapt/defer/reject or unresolved decisions, not just a value ranking, before claiming the issue goal is satisfied.
