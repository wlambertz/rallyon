# Flyway repair verification

The Boot 4.1.2 managed `spring-boot-starter-flyway` replaced the direct Flyway core dependency. A clean PostgreSQL 17 database received existing migrations V1–V5; the service health endpoint returned 200 and a signed organizer request to create a draft returned 201. The same request without a token returned 401. These checks used an isolated test key and database.

`FlywayPostgresIntegrationTest` ran against a dedicated empty PostgreSQL database: both the successful migration and deliberately invalid migration/startup failure scenarios passed. It is enabled in Java CI through a dedicated PostgreSQL service. An existing non-empty database without matching Flyway history can cause Flyway to refuse startup; review its schema and history before rollout, as documented in the README.

On Temurin 25.0.5 with Maven 3.9.14 and temporary Java/Kotlin target overrides of 25, IAM `install` passed (12 tests) and service `clean verify` passed (91 tests, one existing skip), including the PostgreSQL regression test. The actual repository compilation targets remain 21 pending the remaining required delivery validation. No hosted CI run for the revised change has been observed.

The independently reviewed regression test was tightened to use the production application properties, identify the intentional failing SQL, and require an explicit test-database mutation opt-in. The full Java 25 verification was repeated successfully after those corrections. Security suppression validation and 27 security-script tests passed. Local runtime dependency collection and CycloneDX SBOM generation passed; the comparison found all 147 runtime coordinates.

On 2026-11-04, the real OWASP Dependency-Check 13.0.0 scan of those inputs completed with exit 0, 164 report entries and no active vulnerabilities; OSS Index was unavailable without credentials. It used an isolated copy of the previously populated cache and current NVD data. The execution inventory labels the base revision `c99250ab884ec28c1cff05fc071fd2776ff1d194`; the Flyway dependency change was uncommitted, so that revision alone does not identify the scanned source. Hosted jobs have not been run for this change.

The retained Java 21 build also passed IAM install and service clean verify on Temurin 21 after rerunning outside the sandbox, which blocks the IAM tests' loopback socket. That run skipped the two PostgreSQL tests because no dedicated database was configured, in addition to the existing skip. A separate temporary candidate with Java 25 set in the actual POMs, without command-line target overrides, passed clean IAM install and service clean verify on Temurin 25 against isolated PostgreSQL: 91 service tests, one existing skip. At that point the candidate had not been applied to the working tree or exercised by hosted CI.

After that test, the maintainer explicitly approved applying the Java 25 patch as an unmerged CI candidate before hosted checks with the chat quote `go`. This exception permits the candidate in the working tree only; it does not approve commit, push, release, merge or treating the new baseline as accepted. Hosted CI, the independent lifecycle gates and UAT remain pending.
